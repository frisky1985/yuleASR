# HARA - 危害分析和风险评估

> **版本**: 1.1 | **日期**: 2026-07-23
> **变更**: 修正 S/E/C 参数和 ASIL 计算，对齐项目 ASIL-B 目标

## 危害分析方法

基于 ISO 26262-3 进行危害分析和风险评估 (HARA)。

## 修订概要

| 危害ID | 之前 | 之后 | 理由 |
|--------|------|------|------|
| H001 | S3/E4/C3 → D | S2/E4/C2 → B | 参考平台 ASIL-B 场景；E2E 保护提升可控性 |
| H002 | S3/E3/C2 → D(误) | S3/E3/C2 → B | ASIL 查表修正：S3+E3+C2=B |
| H003 | S2/E3/C2 → C(误) | S2/E3/C2 → A | ASIL 查表修正：S2+E3+C2=A |
| H004 | S2/E2/C2 → B(误) | S2/E2/C2 → QM | ASIL 查表修正：S2+E2+C2=QM |

## 识别的危害

| 危害ID | 描述 | S | E | C | ASIL |
|********|******|***|***|***|******|
| H001 | 通信数据损坏（参考平台 ASIL-B 场景） | S2 | E4 | C2 | **B** |
| H002 | 任务超时导致系统响应不及时 | S3 | E3 | C2 | **B** |
| H003 | 数据丢失导致配置错误 | S2 | E3 | C2 | **A** |
| H004 | 计数器错误导致序列混乱 | S2 | E2 | C2 | **QM** |

## 安全目标

### SG-001: 通信数据完整性
- **要求**: 通信数据必须保护免受损坏
- **ASIL**: B
- **实现**: E2E 保护机制 (CRC + Counter + DataID)
- **分解**: B(B) + QM(B) (ISO 26262-9 §5)

### SG-002: 任务定时保证
- **要求**: 关键任务必须在预算时间内完成
- **ASIL**: B
- **实现**: OS Timing Protection + WdgM
- **分解**: B(B) + QM(B) (ISO 26262-9 §5)

### SG-003: 数据持久化可靠性
- **要求**: 关键配置数据必须可靠存储
- **ASIL**: A
- **实现**: NVM 冗余存储 + CRC 校验
