# 双分支并行开发计划

## 概述

日期: 2025-04-28  
版本: v1.0  

本计划定义从master分支移植内容到main分支后，两个分支如何并行发展、定期同步的策略。

---

## 分支定位

### main分支 - ETH-DDS集成中间件

**使命:** 提供完整的车载以太网和DDS中间件解决方案

**核心特性:**
- 完整ETH驱动和协议栈（SoAd、TcpIp、EthSM）
- DDS配置工具和运行时
- TSN/时间敏感网络支持
- Adaptive AUTOSAR兼容性
- 汽车级功能安全（ASIL-D）
- OTA更新和Bootloader
- 多架构支持（CM4F/CM7/CM33）

### master分支 - Classic AUTOSAR标准平台

**使命:** 提供标准的Classic AUTOSAR基础软件平台

**核心特性:**
- 标准Classic AUTOSAR BSW模块
- 完善的OpenSpec文档系统
- RTE代码生成器
- 丰富的ASW组件库
- 高质量文档网站
- 完善的验证框架

## 同步会合机制

### 每周会合

**时间:** 每周五下午4:00  
**形式:** 线上会议

**议程:**
1. 两分支进度汇报 (15分钟)
2. 共享技术分享 (15分钟)
3. 同步需求讨论 (15分钟)
4. 下周计划 (15分钟)

**同步内容:**
- bug修复同步
- 测试用例共享
- 文档更新协调
- 依赖关系确认

### 每月发布

**时间:** 每月第一周周一

**流程:**
1. 两分支代码审查
2. 合并到release分支
3. 打标签（遵循语义化版本）
4. 发布版本说明
5. 更新变更日志

**版本号规则:**
- 格式: `v2.X.Y`
- X: 主版本（重大功能）
- Y: 次版本（bug修复、小功能）

## 代码同步规范

### 同步方向

```
master ----> main (定期合并)
   ^            |
   |            |
   +------------+
   (紧急修复同步)
```

### 同步内容

**必须同步:**
- 关键bug修复
- 安全漏洞修复
- 共享库更新
- 工具链升级

**可选同步:**
- 新功能模块
- 文档更新
- 测试用例

### 同步流程

1. 在源分支创建sync分支
2. 解决冲突（如有）
3. 运行完整测试
4. 创建PR到目标分支
5. 代码审查
6. 合并

## 风险管理

### 识别的风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 两分支差异过大 | 高 | 定期同步，控制分支特性 |
| 资源分散 | 中 | 明确优先级，聚焦核心功能 |
| 同步冲突 | 中 | 规范化同步流程，提前沟通 |
| 测试覆盖不足 | 高 | 自动化测试，强制覆盖率门禁 |

### 应急预案

**分支分裂:**
- 如果两分支差异过大，将main作为主干，master作为维护分支
- 保留master的关键特性逐步移植到main

**资源不足:**
- 优先保证main分支开发
- master分支进入维护模式
