## 1 引言

### 1.1 目的

本报告依据 ISO 26262-9:2018 §5 (ASIL 分解) 的要求，详细阐述 yuleASR AUTOSAR BSW 平台的 ASIL 等级分配策略、分解理由、独立性证明以及与 SWE.6 验收测试的对齐证据。

### 1.2 ASIL 分解概述

yuleASR 采用 **ASIL B(B) + QM(B) 混合分解** 策略，基于以下 HARA 结果：

| 安全目标 | 未分解 ASIL | 分解方案 | 分解后组件 |
|----------|:----------:|----------|------------|
| SG-001: 通信数据完整性 | **B** | B(B) + QM(B) | E2E 保护 (ASIL B) / Com/Can/PduR (QM) |
| SG-002: 任务定时保证 | **B** | B(B) + QM(B) | OS Timing + WdgM (ASIL B) / 任务调度 (QM) |
| SG-003: 数据持久化可靠性 | **A** | 不分解 (保留 A) | NVM (ASIL A) |
| H004: 计数器序列 | **QM** | 不分解 | 常规校验 (QM) |

**ISO 26262-9 §5.4.2** 要求: ASIL B(B) + QM(B) 合并不低于原始 ASIL B ✅

## 4 ASIL 分解理由论证 (ISO 26292-9 §5.4.4)

### 4.1 SG-001: 通信数据完整性 (ASIL B → B(B) + QM(B))

**分解理由**:

通信数据完整性涉及两个层次的组件：
1. **安全数据路径** — E2E 模块负责 CRC 校验、Counter 验证、DataID 确认、故障静默。这些是安全关键操作，必须按 ASIL B 实现
2. **通信传输路径** — Com 模块(信号路由)、PduR(PDU 转发)、Can/Lin/SPI 驱动(物理传输)仅透明传递数据。数据的安全完整性由 E2E 端到端保护保证，传输层不需要额外安全等级

**独立性证明**:
- E2E 模块通过 CRC + Counter + DataID 实现对通信数据完整性的独立保证
- Com/PduR/Can 即使全部失效(不转发/错误转发)，E2E 端到端保护可检测并抑制
- DFA [D03] §5 已验证 FFI 满足率 93%
- **关键风险**: Com 沉默 (不发送任何数据) → E2E 超时监控检测 → 故障静默进入 Safe State

### 4.2 SG-002: 任务定时保证 (ASIL B → B(B) + QM(B))

**分解理由**:

任务定时保证涉及：
1. **OS Timing Protection** — 执行/锁定/间隔时间监控, 安全关键
2. **WdgM** — 看门狗管理, 超时检测与复位
3. **任务本身** (QM 级) — 任务的业务逻辑不涉及安全关键时序功能

**独立性证明**:
- OS Timing 独立监控所有任务执行时间, 不依赖任务自身正确性
- WdgM 通过硬件看门狗提供最终栈保护 (Failsafe)
- 任务超时 → OS Timing 检测 → WdgM 触发 → 系统复位
- **关键风险**: OS 调度器本身失效 → WdgM 喂狗停滞 → 硬件 WDG 触发复位

### 4.3 SG-003: 数据持久化可靠性 (ASIL A — 不分解)

**不分解理由**:
- ASIL A 的安全需求相对较低 (SPFM ≥ 90%, LFM ≥ 60%)
- NVM 模块的整体复杂度可控, 双备份 + CRC 校验已提供超额覆盖
- 单模块 ASIL A 实现的经济性更高 (无需额外的分解管理工作)
- FTA 显示 P(SG-003) = 5.0×10⁻¹⁷ /h, 远超 ASIL A 要求

### 4.4 H004: 计数器序列混乱 (QM — 不分解)

- QM 级无需功能安全措施
- E2E 非安全路径 (或应用层常规校验) 已覆盖

## 5 独立性 (Freedom from Interference) 证明

### 5.1 FFI 分析框架

ISO 26262-9 §5.4.4 要求分解后的模块之间有 **Freedom from Interference**，即 ASIL B(B) 部分不受 QM(B) 部分的干扰导致安全目标违反。

DFA 分析 [D03] 识别了 4 种干扰路径：

| 干扰类型 | ISO 26262-6 §7.4 要求 | 评估 | 缓解措施 |
|---------|----------------------|:----:|---------|
| **内存干扰** | §7.4.6 信息隔离 | ⚠️ 无 MPU, 但有链接脚本分区 | 链接脚本分区 + E2E 端到端保护 |
| **时序干扰** | §7.4.3 时序隔离 | ✅ OS Timing Protection 独立监控 | 执行/锁定/间隔时间监控 |
| **中断干扰** | §7.4.5 中断隔离 | ✅ 中断优先级配置 + WdgM | 硬件 NVIC 优先级分组 |
| **通信干扰** | §7.4.4 通信隔离 | ✅ E2E 端到端保护 | CRC + Counter + DataID |

### 5.2 内存干扰分析

**ASIL B(B) 模块内存布局** (假设链接脚本分区):
```
┌────────────────────────────────────────────────┐
│   S32K312 SRAM (64 KB)                          │
├────────────────────────────────────────────────┤
│  Segment A: ASIL B(B) code/data (16 KB)        │  ← E2E, WdgM, OS Timing
│    - E2E Code + Data            (4 KB)          │
│    - WdgM Code + Data           (3 KB)          │
│    - OS_Timing Code + Data      (3 KB)          │
│    - NvM_CRC Code + Data        (3 KB)          │
│    - RamSafety Code + Data      (2 KB)          │
│    - SecOC Code + Data          (1 KB)          │
├────────────────────────────────────────────────┤
│  Segment B: QM(B) code/data (12 KB)             │  ← Com, Dcm, PduR
│    - Com Code + Data            (5 KB)           │
│    - Dcm Code + Data            (4 KB)           │
│    - PduR Code + Data           (3 KB)           │
├────────────────────────────────────────────────┤
│  Segment C: QM (non-decomposed) (36 KB)          │
│    - Can, Lin, SPI, MCAL, ...                    │
│    - EcuM, BswM, Dem, Det, ...                   │
└────────────────────────────────────────────────┘
```

**无 MPU 场景的缓解**:
- ASIL B(B) 模块仅通过函数调用接口与 QM 模块交互 (E2E_Check / E2E_Protect)
- QM 模块无法直接修改 ASIL B(B) 模块的配置数据
- E2E 端到端保护不依赖 QM 模块的正确性
- DFA 偏差 D-FFI-001 已记录并接受

### 5.3 时序干扰分析

| 场景 | 失效率评估 | 缓解 | 残留风险 |
|------|:---------:|------|:--------:|
| QM 任务占用 CPU 过久 | λ = 6 FIT (执行超预算) | OS Timing 监控 → 中断 | 0.6 FIT |
| QM 中断频繁抢占 | λ = 4 FIT | NVIC 优先级 + WdgM | 0.4 FIT |
| QM DMA 堵塞总线 | λ = 3 FIT (总线 DFA) | DMA 优先级限制 | 0.3 FIT |

**时序 FFI 结论**: QM 模块对 ASIL B(B) 模块的时序干扰风险可控。OS Timing Protection 提供执行时间监控，WdgM 提供最终保护。
