MISRA C:2012 Rule Texts

This file contains MISRA C:2012 rule texts for cppcheck misra addon.

Appendix A  Summary of guidelines

Rule 2.2 Required
Source code shall only use /* ... */ style comments

Rule 2.3 Advisory
The character sequence /* shall not be used within a comment

Rule 2.4 Advisory
A section of code shall not be commented out using slash-star

Rule 2.5 Advisory
A project should not contain unused macro declarations

Rule 2.7 Advisory
There should be no unused parameters in functions

Rule 5.6 Advisory
A typedef name shall be a unique identifier

Rule 5.7 Advisory
A tag name shall be a unique identifier

Rule 5.8 Advisory
Identifiers that define objects or functions shall have unique names

Rule 5.9 Advisory
Identifiers that define objects or functions shall be unique before linker stage

Rule 7.2 Required
A cast should not remove any const or volatile qualification

Rule 7.4 Required
String literal assigned to pointer shall have const-qualified char type

Rule 8.2 Required
Function types shall be in prototype form with named parameters

Rule 8.4 Required
A compatible declaration shall be visible when an object or function is defined

Rule 8.5 Required
An external object or function shall be declared once in one file

Rule 8.6 Required
An identifier with external linkage shall have exactly one external definition

Rule 8.7 Required
Functions/objects should not have external linkage if referenced in one TU

Rule 8.8 Advisory
Static storage class shall be used for internal linkage declarations

Rule 8.9 Required
An identifier with internal linkage shall have exactly one definition

Rule 8.11 Required
Array with external linkage shall have explicit size

Rule 9.2 Required
Initializer for aggregate/union shall be enclosed in braces

Rule 9.3 Advisory
"=" shall not be used to explicitly define enumerator values

Rule 10.1 Required
Operands shall not be of an inappropriate essential type

Rule 10.3 Required
Complex expression shall only be assigned to same essential type category

Rule 10.4 Required
Both operands shall have same essential type category

Rule 10.6 Required
Composite expression shall not be assigned to wider essential type

Rule 10.7 Required
Other operand shall not have wider essential type

Rule 10.8 Required
Composite expression shall not be cast to different essential type

Rule 11.3 Required
Cast between pointer to different object types shall not be performed

Rule 11.4 Required
Conversion between pointer to object and integer shall not be performed

Rule 11.5 Required
Conversion from pointer to void to pointer to object shall not be performed

Rule 11.6 Required
Cast between pointer to void and arithmetic type shall not be performed

Rule 11.8 Required
Cast shall not remove const/volatile from pointer qualification

Rule 12.1 Advisory
Operator precedence within expressions should be made explicit

Rule 12.3 Advisory
The comma operator should not be used

Rule 13.3 Required
Increment/decrement expression should have no other side effects

Rule 14.4 Required
Controlling expression of if shall have essentially Boolean type

Rule 15.1 Advisory
The goto statement should not be used

Rule 15.4 Advisory
No unconditional branch to case label in switch

Rule 15.5 Advisory
A function should have a single point of exit

Rule 15.6 Required
Body of iteration/selection statement shall be compound

Rule 15.7 Required
All if-else-if constructs shall be terminated with else clause

Rule 16.3 Required
Unconditional break shall terminate every non-empty switch clause

Rule 17.2 Required
A function should not call itself directly or indirectly

Rule 17.3 Required
A function shall not be declared implicitly

Rule 17.7 Required
Return value of non-void function shall be used

Rule 17.8 Advisory
A function parameter should not be modified

Rule 18.4 Required
Pointer arithmetic operators should not be applied to pointer type

Rule 19.2 Advisory
The union keyword should not be used

Rule 20.2 Required
The hash and double-hash preprocessor operators should not be used

Rule 20.9 Required
Preprocessor identifiers shall be defined before use

Rule 21.3 Required
Memory allocation functions of stdlib.h shall not be used

Rule 21.8 Required
The atof, atoi and atol functions of stdlib.h shall not be used
